数据如何流转

追踪一条视频数据从输入到最终笔记的完整旅程，理解每个环节传递了什么。

一条视频数据的完整旅程

把整个管线想象成一场接力赛。数据是接力棒，每个函数是一位选手。

1
用户输入 BV号

resolve_input() 解析输入，提取出 BV 标识符

2
汇聚原始素材

fetch_all() 收集视频信息、字幕文本、评论列表、音频路径

3
没有字幕？听写出来

若视频无字幕，transcribe() 将音频转为文字

4
抽取关键帧图片

extract_keyframes() 分析画面变化，截取关键帧

5
理解每一帧画面

analyze_frames() 用视觉模型给每帧生成文字描述

6
合成最终笔记

generate_note() 将所有素材交给 LLM 生成 Markdown

7
存入 Obsidian 仓库

笔记文件保存到 Obsidian vault，流程结束

💡
接力赛比喻

每个函数是一位选手。选手 1 把棒交给选手 2，选手 2 跑完自己的赛段再交给下一位。配置文件则是教练的战术板。

配置文件是控制中心

config.yaml 告诉每位选手该怎么跑，get_llm_client() 负责根据战术派出对应选手。

YAML 

omlx:
  base_url: "http://localhost:8000/v1"
  llm_model: "Qwen3.6-35B-A3B-nvfp4"
  vlm_model: "Qwen3-VL-8B-Instruct-MLX-4bit"

obsidian:
  vault_path: "~/Documents/Bilibili/Bilibili"
  notes_dir: "video-notes"

frames:
  scene_threshold: 0.3
  max_frames: 20
白话翻译

本地 AI 服务的地址和两个模型名称：

llm_model = 负责写笔记的文本选手

vlm_model = 负责看图的视觉选手

 

笔记保存到哪里——vault_path 是根目录

notes_dir 是笔记子文件夹

 

抽帧策略：scene_threshold 越小越敏感

max_frames = 最多截 20 张关键帧图片

PYTHON 

def get_llm_client(config, provider=None):
    provider = provider or config.get("provider")
    if provider == "minimax":
        client = Anthropic(base_url=..., api_key=...)
        return client, model, "anthropic"
    else:
        client = OpenAI(base_url=config["omlx"]["base_url"])
        return client, model, "openai"
白话翻译

检查用哪个 AI 服务——默认读配置文件

如果选了 MiniMax 云端服务：

用 Anthropic 格式的 API 连接远程服务器

返回客户端、模型名、API 类型

否则用本地 oMLX 服务：

用 OpenAI 格式的 API 连接本地服务

返回客户端、模型名、API 类型

🔑
分层解耦

配置文件和代码是分层解耦的。改模型只需改 YAML，不用动代码；换服务商只需改 provider 字符串，get_llm_client() 自动适配。给 AI 下指令时可以说："实现分层配置，运行时根据 provider 字符串切换 API 客户端。"

字典 (dict)

fetch_all 返回的数据容器——像一份打包清单，里面装着视频信息、字幕、评论等不同类型的数据。

🎬

文件路径 (Path)

extract_keyframes 返回的是 PNG 图片文件路径列表——每张图片对应视频中的一个关键时刻。

👁️

描述字符串 (str)

analyze_frames 给每帧加上文字描述——从图片到文字，让 LLM 能够理解画面的内容。

📝

Markdown 文件

最终产物——一份结构化的 .md 文件，直接保存到 Obsidian vault 中供阅读和搜索。
